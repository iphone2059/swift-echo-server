## Required changes

1. **P0 missing completion drain**: `CECEngineWorker.swift:78,385,399` closes sockets and removes every timer. A missing last RIO/ConnectEx completion leaves `liveSessions` nonzero forever. Preserve first-close QPC deadline + 5000ms, emit pure DrainTimeout action, and verify native ownership inside Transport before fail-fast `client generation drain`/1460. Repeat stop cannot extend grace.
2. **P0 fake notification**: `CECEngineWorker.swift:672` synthesizes an IOCP packet and calls it notification delivery. Remove this protocol. Consume only real delivered notifications; after native outstanding reaches zero, allow residual notify arms-deliveries 0 or 1. Close CQ before notification allocation release, retain native storage until provider cannot reference it.
3. **P0 release boundary**: `CECEngineWorker.swift:638` checks ownership only when thread handle exists. Put unconditional native per-operation/all-session/aggregate checks inside actual release function, including never-started partial owners. Check started/joined phase/live/timer invariants separately. Keep named fail-fast before any CQ/registration/arena release.
4. **P0 Join barrier**: `CECEngine.swift:122` joins/checks/releases each worker in one iteration. Split coordinator into Join-all, check-all, snapshot-all, release-all. Preserve partial startup and idempotent owner deinit.
5. **P0 operation ownership**: `CECEngineInternal.swift:49` has only a shared outstanding count. Add independent ConnectEx/send/receive posted flags, exact posted lengths, generation and once-only drain-report marker; validate result context, generation, operation, counts and byte range before decrement. Duplicate receive cannot retire a pending send.
6. **P1 pure architecture**: `CECEngineSession` and `CECEngineWorker` mix pure business state with socket/RQ/OVERLAPPED/buffer/native counts. Introduce independent pure Session/Scheduler/WorkerCore in internal, native Slot/RioTransport, normalized Completion and Event/Action contracts, generic static WorkerRuntime. Scheduler cannot inspect native fields or call native APIs. Transport never reads business state. Completion -> Event -> Core -> Action -> Runtime -> Transport.
7. **P1 arbitration**: `cecDrainCompletions` drains until empty, calling service/timers between batches. Current references drain max64 batches then settle control before due timers, and before timers acquire <=sessions+2 queued packets plus <=2*sessions CQ records. Captured records must settle before stop/deadlines; newly produced traffic cannot get unbounded priority. Preserve receive-before-send post order, whole-send-tail normalization, no new attempt until both operations retire.
8. **P1 timers**: Swift timer heap uses GetTickCount64 while latest references keep worker timers in cached QPC ticks, ceiling wait conversions and fresh posting-boundary anchors. Coordinator elapsed/run/report remain GetTickCount64. Validate QPC failures, saturating deadlines, fixed whole-attempt timeout and pacing after verification. Request time must be sampled after preceding validation/socket prep.
9. **P1 arena contract**: `cecInitializeWorker` shares one TX region and allocates `(sessions+1)*batch`. Current references budget/allocate independent TX/RX registration ranges per slot, `2*sessions*batch`, per-worker memory share `(totalMemory/totalSessions)*workerSessions`; use matching layout, validation and initialization rollback order. Register send and receive per-slot windows independently.
10. **P1 ledger/output**: Swift metrics omit cancelled, sent_bytes, received_bytes, connections, reconnects, active, attempted/pending fields. Add worker-local business counters and native successful send-prefix bytes; remove request-path global atomic quota increments. Controlled stop settles as cancelled, fatal stop as lost, partial-tail repost never claims again, untouched finite quota is terminal unclaimed/lost exactly as current references. Output field order and 64-bin batch histogram must match C++. Debug terminal identity includes cancelled and active=0.
11. **P1 native failures**: Swift CECNativeError loses domain/category/retryability. Add shared normalized failure metadata. Initialization failure, connection failure, invariant, drain timeout remain distinct; reporting captures correct API error immediately. QPF precedes native worker heap initialization; preparation OOM must be recoverable rather than UniqueArray/.allocate trap. Canonical current failure stage/exit behavior matches latest `54a1bca`/`371b02f`, including RIONotify duplicate arm, dequeue extent and ConnectEx submitted byte range.
12. **F1 physical mapping**: merge real responsibility into `{contract,types,payload,metrics,native,internal,engine}.swift` + executable `main.swift`. `Package.swift` is Swift module declaration exception to Rust lib.rs/Zig root.zig; no empty ninth business source. Consolidate constants->types; failure/arena/owners->native; timer/session/core/publication->internal; worker runtime/transport/coordinator->engine.

## Risks and evidence to preserve

- Swift ~Copyable/span borrow does not itself guarantee provider completion. Native contexts remain heap-pinned through join/CQ close. Do not put nonescapable Span in a long-lived native slot or synthesize validity through ownership conversion.
- Action dispatch may synchronously yield completion, emit close and yield GenerationDrained: use fixed depth-separated preallocated action regions so nested delivery never overwrites the executing action batch.
- Existing state tests directly mutate mixed session storage. Adapt fixtures to separate core/slot state while preserving expected behavior/counts. Add pure sequence fixtures and fail-fast positive controls, missing-last-completion bounded subprocess, Join-before-guard and release-before-order proof.
- `docs/echo-contract.md` predates current `echo-binary-contract-v1` actual baseline and contradicts current batch/WAITALL/short-TCP/corruption continuation/64-bin contract. This task follows explicitly selected current implementations; do not independently introduce old pipeline semantics.
- E0/performance acceptance needs later generated-code/allocation/baseline evidence. Static refactor or functional green cannot claim formal E0 passed.
